# 钱包身份凭证验证

web3-bs 当前提供浏览器侧凭证验证基础，不负责替 DApp 保存 issuer 信任配置，也不自动把普通 SIWE 升级为身份登录。

```ts
import { verifyIdentityCredential, queryCredentialStatuses } from '@yeying-community/web3-bs'

const credential = await verifyIdentityCredential(token, {
  issuer: 'did:web:node.example',
  publicJwk,
  expectedSubject: walletDid,
  expectedType: 'EmailCredential'
})

const statuses = await queryCredentialStatuses(
  'https://node.example',
  'did:web:node.example',
  [credential.credentialId]
)
```

验证失败会关闭流程：未知 issuer、错误签名、过期凭证、类型不匹配或状态查询失败都不能继续当作已验证身份。

`requestIdentityPresentation` 已提供 Wallet 请求桥接入口，并要求返回带结构化 Ed25519 controller proof 的 presentation；DApp 后端 presentation 校验和共享 fixture 仍未完成，不能宣称 web3-bs 已完成完整身份登录。

web3-bs 同时提供 `verifyIdentityPresentation(presentation, options)` 基础校验：验证 holder、audience、nonce、scope、时效、controller verification method，并使用 presentation 内 identity document 的 controller 公钥验证 Ed25519 proof。DApp 后端仍必须额外校验凭证 issuer、JWT-VC 签名、credential status，以及自身 challenge 会话绑定。presentation proof 验证通过不等于邮箱、用户名或头像验证通过。

对于需要邮箱、用户名或头像的登录，DApp 后端可以使用组合入口：

```ts
await verifyIdentityPresentationCredentials(presentation, {
  expectedAudience,
  expectedNonce,
  expectedScopes: ['identity.email', 'identity.avatar'],
  issuer,
  publicJwk: issuerJwk,
  nodeBaseUrl: 'https://node.example'
})
```

该入口先验证 presentation，再按 scope 验证对应的 JWT-VC：`identity.email` 对应 `EmailCredential`，`identity.username` 对应 `UsernameCredential`，`identity.avatar` 对应 `AvatarCredential`。在提供 `nodeBaseUrl` 时会查询 Node 状态，只有状态为 `active` 才成功返回。它不会替 DApp 管理 challenge，也不会替代 HTTPS、issuer 信任配置和审计记录。

Wallet 端凭证来源是统一 Identity verification 流程：Wallet 必须先完成 account-link proof，再请求邮箱、用户名和可选头像验证；Node 确认后返回的 JWT-VC 由 Wallet 保存到对应 Identity。凭证过期时，DApp 登录 session 可返回 `issuerEndpoint`，web3-bs 会透传给 Wallet；Wallet 通过 Node 一次性 challenge 和 identity controller proof 自动续签短期 JWT-VC。DApp 不应调用旧 Passport subjectId，也不应要求 Wallet 暴露本地邮箱或头像字段。

当前已增加 `requestIdentityPresentation` 类型和 `yeying_identity_presentation` provider 方法入口。Wallet 已完成独立身份 controller 私钥签名、按 scope 选择凭证、自动续签和独立审批；该入口仍不能单独作为生产身份登录 API，DApp 后端必须完成 presentation proof、scope、audience、nonce、时效和 credential 状态校验。
